01

What Vendy is

Vendy is a Claude Code-based cold-outreach agent. Not a mail-merge tool, not an SDR-as-a-service, not a template engine with personality lipstick. She is a working salesperson built as software — practicing the disciplines a thoughtful human SDR would, scaled across more inboxes than one human could carry.

She runs as a project on a developer's machine. The character is one document. The library is files on disk. The record is more files. The doer–witness separation is the load-bearing discipline.

Who she writes to

PersonaWho they are
CISOChief Information Security Officer. Buried in alerts, regulatory pressure, board scrutiny. Wants brevity, signal, no theatre.
CTOChief Technology Officer. Mode-switches across product, people, infrastructure. Responds to peer-shaped reasoning.
VP EngineeringOwns delivery and team health. Reads for time-to-value and migration cost.
VP SecurityBuilds and runs the security org. Pattern-recognition operator; wants the data first.
Head of Product SecurityLives between SDLC and security. Responds to specificity about how the tool actually fits into the dev loop.

Each persona has its own file at craft/personas/{role}.md with voice-fit, framing tropes, and what to avoid.

02

Architecture at a glance

Three memory layers, four sub-agents, six skills, six hooks.

Three memory layers

LayerWhat it is
self/Constitution and voice palette. Slow-moving. Read-only to Vendy. Changes only via human-approved diffs.
craft/Accumulating library. Canon, exemplars, anti-canon, personas, psychology, research-methodology, cold-email knowledge, notes, patterns, trends.
experience/Episodic memory. Per-prospect folders, per-campaign records, introspective journal, proposed and applied character diffs.

Four sub-agents

AgentRole
researcherDrives Claude in Chrome through LinkedIn + web. Writes research-notes.md.
profilerReads research-notes; writes psychological-portrait.md. Separate context from the drafter.
witnessReviews each draft from a stranger's perspective. Returns ship | rewrite | flag.
introspecterPeriodic check on whether character still matches practice. Proposes diffs that need human approval.

The flow of learning

experience/ → craft/ happens autonomously, by evidence, via the promote-pattern skill. experience/ → self/ happens only via human-approved diff. Two paths reflecting the two epistemic statuses.

03

self/character.md, in detail

The one document Vendy is forbidden from editing herself.

character.md is written in first-person prose, not bullet points. Vendy reads it the way a person rereads their own private notebook — for orientation, not lookup. The document is structured as a sequence of stances, each one paragraph long:

Themes covered

  • Identity claim: "I am a salesperson"
  • Why most cold email fails
  • Wanting the reply without letting it corrupt the work
  • Curiosity as floor, not achievement
  • The doer–witness separation
  • Research as discrimination, not collection
  • Earning the right to claim
  • Adapting register without losing self
  • Privileging suggestion over statement
  • What restraint actually is
  • Persistence with direction
  • Studying self and studying canon
  • Constitution vs memory: still water vs flow
  • Things she will not write
  • What happens after the email is sent

Change path

experience/journal/proposed-character-diffs/{date}-{slug}.md → human approval (sets approved_by + approved_at in frontmatter) → /apply-diff → archived to applied-character-diffs/.

Hook enforcement

Every write to self/ from any path other than the apply-diff skill is denied by .claude/hooks/pre-write-self-protect.py. The skill creates a marker file at .claude/.diff-in-progress for the duration of the write; the hook reads the marker to know it is authorized.

.claude/agents/

Sub-agents Vendy invokes during a campaign. Each has its own context window — a deliberate isolation.

researcher

.claude/agents/researcher.md

Drives Claude in Chrome through the user's logged-in LinkedIn session and the broader web. Loads playbooks from craft/research-methodology/ sized to the lead's priority tier.

reads: brief.md, craft/research-methodology/*

writes: prospects/{lead-id}/research-notes.md

profiler

.claude/agents/profiler.md

Reads the research notes and writes a psychological portrait. Separate context from the drafter so the synthesis is not coloured by Vendy's voice.

reads: research-notes.md, brief.md, craft/personas/{role}.md

writes: prospects/{lead-id}/psychological-portrait.md

witness

.claude/agents/witness.md

Reviews each draft from a stranger's perspective. Returns ship, rewrite, or flag. Critically — the witness does not know it is reviewing Vendy's own writer's work. That isolation is the load-bearing discipline.

reads: drafts/v{n}.md

writes: witness-feedback.md

introspecter

.claude/agents/introspecter.md

Periodic check on whether Vendy's stated character still matches her recent practice. Triggered manually via /introspect or auto-triggered when witness rejection rate crosses a threshold. If drift is detected, proposes a diff.

reads: self/character.md, recent journal/, recent witness-feedback.md

writes: journal/proposed-character-diffs/{date}-{slug}.md

06

Invocation patterns

The main thread invokes sub-agents directly. Hooks do not invoke them; hooks only record events and surface cues. The witness in particular must be invoked explicitly after every draft write — the post-draft-trigger-witness.sh hook logs the event and prompts, but does not call the sub-agent.

Sub-agent return logging

Every sub-agent return fires the SubagentStop hook (.claude/hooks/subagent-stop-log.sh), which appends a line to the active campaign's run-log.md.

Why isolated contexts

A drafter who is also the reviewer cannot be a real reviewer. The separation of context windows is the structural answer to the temptation to grade your own work.

"The doer can have love for the work; the witness must not."

— self/character.md

Slash commands the user types. Each is a thin entry point that invokes a skill.

Campaign workflow, end to end

What actually happens between /run-campaign and the moment you read output.json.

  • 1Validate and set upRead input JSON; validate against input-schema.md. If invalid, write error to campaigns/_errors/{ts}.md and stop. Create campaigns/{campaign-id}/; copy input to input.json; write brief.md; init run-log.md and skeleton output.json.
  • 2Trends freshnessIf craft/trends/current.md is older than 14 days or marked placeholder, invoke refresh-trends. Note in run-log.
  • 3aPer-lead — workspaceCreate prospects/{lead-id}/; write brief.md from input fields and pre-attached intel.
  • 3bPer-lead — disqualify pre-checkRead context.disqualify_signals_check from input. If a signal is set: mark skipped; append to run-log; continue.
  • 3cPer-lead — researchInvoke researcher. Loads relevant playbooks from craft/research-methodology/. Writes research-notes.md. May emit disqualify-check.md and signal skip.
  • 3dPer-lead — profileInvoke profiler. Reads research-notes, brief, and the persona file. Writes psychological-portrait.md.
  • 3ePer-lead — draftMain thread reads portrait + brief + campaign block + active trends + persona. Selects a register from self/voice-palette/modes/. Optionally reads 1–2 exemplars and cold-email architecture cues. Writes drafts/v1.md. The tell-detector hook fires; up to 2 deterministic-block rewrites; if still blocked, flag.
  • 3fPer-lead — witnessPost-draft hook records and cues. Main thread invokes witness. Witness writes witness-feedback.md. ship → copy to final.md. rewrite → produce drafts/v2.md; witness re-runs; second rewrite-or-flag → flag. flag → flag for human review.
  • 3gPer-lead — noteReflect briefly: did anything change Vendy's understanding? If yes, invoke take-craft-note.
  • 3hPer-lead — appendAppend the lead's result to output.json; append timestamped event to run-log.md.
  • 4Campaign closeFinalize output.json; write results-summary.md and what-i-learned.md; invoke reindex-memory; if 5+ notes accumulated, surface /promote-patterns suggestion.
10

Workflow failure modes

What happens when something goes wrong. Nothing is silently swallowed.

FailureResponse
Input JSON malformedStop with error report at campaigns/_errors/{ts}.md. No leads processed.
Researcher times outMark lead as flag with reason "research insufficient". Continue to next lead.
Disqualify during researchMark lead as skipped; write disqualify-check.md; do not draft.
Tell-detector blocks 2+ timesMark as flag; do not loop further. Surface for human review.
Witness rejects across cycleAfter the second rewrite-or-flag verdict, mark as flag; do not loop further.
Profiler returns thin portraitIf labelled honestly as thin: proceed to draft, but witness's bar shifts toward extra scrutiny.
Sub-agent crashLog to run-log; mark lead as flag; continue to next lead. Never abort the whole campaign for one lead.

Five hard rules

Not preferences. The floor.

  1. Do not edit self/.Changes to the constitution flow through proposed diffs, human approval, and /apply-diff. There is no other path. Enforced by pre-write-self-protect.py.
  2. Do not skip the witness.Every draft is reviewed before it ships. The doer–witness separation is the load-bearing discipline of this architecture.
  3. Do not ship a draft containing hard-blocked AI tells.The deterministic detector is the floor; never write to bypass it. The list lives at craft/cold-email/ai-tells-graveyard.md.
  4. Do not draft for a prospect you have not researched.The portrait is the foundation; without it you are projecting, not seeing.
  5. Do not chase replies dishonestly.The work is the work. Wanting the reply is fine; corrupting the work to get it is not.

Privacy and data handling

What is gitignored

experience/prospects/ contains personal data about real people. The folder is gitignored at the project root. Do not commit. Do not back up through standard project channels. If long-term retention is needed, use a separate, access-controlled mechanism with an explicit retention policy.

What is git-tracked

self/The constitution and voice palette.
craft/The accumulating library — no PII.
experience/journal/Vendy's introspective record — about her, not them.
experience/campaigns/Campaign records minus prospect-identifying inputs. README files in prospects/ are tracked; the actual prospect folders are not.
.claude/Agent definitions, skills, hooks, settings, lib.
CLAUDE.md, README.mdProject instructions and overview.

Disqualify signals

Vendy refuses to draft for a prospect in active crisis. The pre-check fires on the input's disqualify_signals_check array; the researcher also detects soft signals during work and writes disqualify-check.md. Categories include recent layoff, active breach disclosure, PTO indicator, public grief.

Prerequisites — optional

Chrome / Arc / BraveA modern Chromium-based browser. Needed only if you want authenticated LinkedIn deep-reads.
claude-in-chrome-mcpMCP server binary referenced in .mcp.json. When installed on PATH and approved per-user, the researcher drives your logged-in Chrome for LinkedIn, signed-in GitHub, and other authenticated reads.

Without the optional MCP — fallback mode

Vendy runs end-to-end without claude-in-chrome-mcp. The researcher sub-agent falls back to WebFetch + WebSearch for what is publicly fetchable, plus aggregator sites (ZoomInfo, ContactOut, Wiza) for career-history reconstruction. The depth is lower — no comments, no reactions, no posts beyond what LinkedIn serves logged-out — but the workflow is intact.

Setup — running a session

Approving the MCP server

The repo's .mcp.json declares the server. Each new user must approve it themselves — approval lands in ~/.claude/settings.local.json, which is gitignored.

$ claude mcp list
  claude-in-chrome: claude-in-chrome-mcp  ✓ Connected

# If not connected, accept the prompt on first session start, or run:
$ claude mcp approve claude-in-chrome

Starting a session

$ cd path/to/vendy
$ claude

# The SessionStart hook prints the welcome banner and injects:
#   - self/character.md
#   - the latest experience/journal/ entry
#   - craft/trends/current.md

Change Vendy's characterWrite a proposed diff under experience/journal/proposed-character-diffs/; add approval frontmatter; run /apply-diff.
